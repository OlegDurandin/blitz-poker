# Blitz Poker Solo

Короткий матч в heads-up Texas Hold'em против бота «Бот Алекс». Это VK Mini App.
Матч длится 8 раздач, стеки 600/600, блайнды растут каждые две раздачи.

> **Только для развлечения.** Фишки виртуальные, существуют только внутри матча.
> Их нельзя купить, продать или вывести. Ставок на деньги нет.

## Структура

```
crates/
  poker-core/   правила: карты, оценка руки, машина состояний матча, снимок для сохранения
    src/history.rs   запись раздачи для одного места (HandRecord) и пошаговый повтор (replay)
    src/table.rs     стол на 2–6 мест: побочные банки, выбывание, места («Третий не лишний»)
  bot/          Бот Алекс: решает только по PlayerView своего места
    src/preflop_table.rs   эквити 169 стартовых рук heads-up (генерирует examples/gen_preflop.rs)
    src/reference.rs       эталонные соперники для тестов и стенда
    src/table.rs           боты за столом на 3+ (decide_table); вдвоём — та же логика дуэли
    examples/table_arena.rs  турнир характеров за столом на троих
    examples/evaluate/     стенд оценки бота, включая замороженную копию бота 1.0
  poker-wasm/   мост JSON ⇄ WASM для веб-клиента (без wasm-bindgen)
  pvp-server/   сервер дуэлей с другом (axum + SQLite): комнаты, WebSocket, проверка VK
web/            клиент VK Mini App: React + TypeScript + Vite + vk-bridge
  src/pvp/                 сетевой клиент дуэли
  src/screens/Duel.tsx     приглашение, комната, стол, итог и реванш
deploy/         systemd-юнит и пример Caddy для сервера дуэлей
  src/screens/Stats.tsx    статистика и список последних матчей
  src/screens/History.tsx  раздачи одного матча
  src/screens/Replay.tsx   пошаговый повтор раздачи
```

### Архитектурные контракты (из UX-спеки, §10)

- **Движок — единственный источник истины.** UI получает `PlayerView` и отправляет `PlayerAction`.
  Банк, легальные действия, диапазон рейза, пресеты (½ банка / банк / олл-ин) и победителя
  считает только `poker-core`.
- **Бот не видит скрытых карт.** `bot::decide` принимает только `PlayerView` своего места:
  там его карты, борд и история ставок. Доступа к колоде и картам человека у него нет.
- **Сохранение без перетасовки.** Снимок `Match` хранит версию схемы, 9 сданных карт и состояние
  ГСЧ. После перезагрузки рука продолжается с той же колодой. Сохранение происходит после каждого
  подтверждённого перехода. Повреждённый снимок или снимок несовместимой версии ведёт на отдельный
  экран с кнопкой «Начать новую игру».
- **Инвариант фишек:** `стеки + ставки + банк = 1200` на каждом переходе. Это проверяет fuzz-тест
  на 3000 случайных матчах.
- **История не раскрывает лишнего.** Внутри движка `HandSummary` хранит карты обоих игроков. Наружу
  уходит только `HandRecord`, спроецированный на одно место: свои карты всегда, карты соперника
  только после вскрытия, борд только открытый. Эту же проекцию получает и бот.
- **Повтор не пересчитывает правила.** `replay` двигает ровно те фишки, которые записал движок, и
  проверяет, что итог совпал с записанным. Fuzz-тест на 1500 матчах сверяет каждое состояние живой
  игры с кадрами повтора. Повтор только читает запись и никогда не меняет текущий или сохранённый матч.

## Запуск

Нужны Rust (stable) с таргетом `wasm32-unknown-unknown` и Node 22.12+ (в `.nvmrc` указана 24, `nvm use` её подхватит).

```bash
rustup target add wasm32-unknown-unknown

cargo test --workspace --release   # движок, история, бот, мост (~70 с из-за тестов бота)
cargo run -p bot --release --example evaluate 300   # отчёт о силе и поведении бота (~3 мин)

cd web
npm install
npm run dev        # собирает WASM и открывает http://localhost:5173
npm test           # vitest: реальный WASM-движок, история, архив и статистика
npm run build      # production-сборка в web/dist
```

`npm run wasm` пересобирает `crates/poker-wasm` и кладёт `poker.wasm` в
`web/src/engine/generated/`. Эта папка не хранится в git.

## Хранение данных

Всё хранится в `localStorage` WebView, без сервера:

| Ключ | Что внутри |
|---|---|
| `blitz.v1.match` | снимок текущего матча (`Match`, схема `SCHEMA_VERSION = 1`) и метаданные сессии |
| `blitz.v1.tutorial`, `blitz.v1.tutorial_done` | учебная раздача |
| `blitz.v1.stats` | статистика, версия `v: 3` (с разбивкой побед по соперникам) |
| `blitz.v1.opponent` | последний выбранный соперник |
| `blitz.v1.table` | снимок текущего стола «Третий не лишний» (`Table`, схема `TABLE_SCHEMA_VERSION = 1`) |
| `blitz.v1.table_stats` | столы: сыграно, места, прерванные, версия `v: 1` |
| `blitz.v1.table_bots` | последний выбранный состав ботов за столом |
| `blitz.v1.duel_room` | id комнаты текущей дуэли: после перезагрузки WebView игрок возвращается в неё |
| `blitz.v1.archive` | список id последних матчей, новые первыми (не больше 30) |
| `blitz.v1.archive.<id>` | один завершённый или прерванный матч: итог и `HandRecord` всех раздач, версия `v: 1` |

**Соперник** хранится в снимке матча (`Match::opponent`) и в записи архива. В сохранениях и
архивах до 1.2 его нет, такие матчи считаются матчами против Алекса.

**Миграция с 1.0 без сброса.** У сохранённого матча 1.0 в истории нет стартовых стеков и карт.
Он загружается как есть: `Match::upgrade` восстанавливает стартовые стеки по результатам раздач, а
карты таких раздач в повторе показываются как «не сохранились». Статистика 1.0 читается в новую
структуру, новые поля начинаются с нуля. Архив появляется только для матчей, сыгранных в 1.1.

**Повреждённые данные.** Каждый матч архива лежит под своим ключом. Нечитаемая запись
пропускается, а экран статистики сообщает, сколько записей не прочитано. Если испорчен сам список
id, он восстанавливается по ключам. Ошибка записи архива не мешает игре и уходит в аналитику как
`persistence_error`.

**Статистика** обновляется один раз на матч: повторная запись с тем же `match_id` ничего не меняет
(хранятся последние 50 id). Прерванные матчи считаются отдельно, обучение не считается.
Доля побед = победы / (победы + поражения); пока знаменатель равен нулю, показывается «—».

## Подключение к VK

Mini App регистрируется как **приложение**, а не через токен сообщества:

1. Создайте приложение типа «Mini App» на [vk.com/editapp?act=create](https://vk.com/editapp?act=create).
2. Запишите его числовой ID в `.env` в корне репозитория: `VK_APP_ID=12345678`.
3. Разработка внутри VK: `cd web && npm run tunnel`. Команда поднимает dev-сервер и HTTPS-туннель
   (`vk-tunnel`) и сама прописывает адрес туннеля как dev-URL приложения. При первом запуске
   нужно подтвердить вход в VK по ссылке из терминала.
4. Выкладка на хостинг VK: `cd web && npm run deploy`. Команда собирает `web/dist` и загружает его
   через `@vkontakte/vk-miniapps-deploy` (настройки в `web/vk-hosting-config.json`). Деплой спросит,
   обновлять ли prod- и dev-URL. Для CI можно передать `MINI_APPS_ACCESS_TOKEN`.
5. Привяжите Mini App к сообществу, чтобы он запускался из группы.

Токен сообщества понадобится, только если нужен ещё и чат-бот в сообщениях группы. Например, он
может отвечать кнопкой «Играть», которая открывает Mini App. Для самой игры токен не нужен.

## Что сделано по спецификации

- Экраны: главная, учебная раздача с тремя контекстными подсказками, стол, окно выбора рейза,
  showdown с подсветкой лучших пяти карт (зелёная рамка у ваших, золотая точка у карт бота),
  итог руки, итог матча, история раздач, правила, пауза, экран ошибки сохранения.
- Состояния стола: `BOT_THINKING`, `PLAYER_TURN_NO_BET`, `PLAYER_TURN_FACING_BET`, `RAISE_EDITOR`,
  `ALL_IN_RUNOUT` (карты открываются по одной, анимацию можно пропустить), `SHOWDOWN`,
  `HAND_SUMMARY`, `MATCH_RESULT`.
- Блок действий имеет фиксированную высоту и не прыгает. Есть safe-area, проверены ширины 320 и 375.
  Учитывается `prefers-reduced-motion`. У карт и кнопок есть доступные имена («Туз пик», «Уравнять 30»).
- Статистика: победы, поражения, ничьи, прерванные, доля побед, текущая и лучшая серия, раздачи,
  самый крупный выигранный банк. Брошенный матч считается отдельно и не идёт в поражения.
- История (1.1): «Статистика и история» на главной → последние матчи → раздачи матча → повтор.
  С экрана итога: «История раздач» → повтор. В повторе есть шаги «В начало / Назад / Вперёд /
  В конец» (и стрелки на клавиатуре), счётчик шагов, подпись к каждому шагу и подсветка
  комбинаций на вскрытии.
- Подсветка на вскрытии: ваши пять карт отмечены голубой меткой сверху, карты соперника —
  янтарной снизу. У общей карты, которая входит в обе пятёрки, видны обе метки. Остальные карты
  приглушены. Нажатие на подпись игрока оставляет только его пятёрку. Строка причины объясняет
  итог: «Фулл-хаус сильнее двух пар», «Решил кикер…», «Ничья — у обоих лучшая пятёрка на столе».
  Цвет означает игрока, а не победителя. Так же устроены Solo, повтор и дуэль.
- Аналитика собирается через `web/src/game/analytics.ts`. Транспорт пока не подключён:
  его нужно передать в `setTransport`. В 1.1 добавлены `match_history_opened`,
  `hand_replay_opened`, `hand_replay_stepped` (число шагов при закрытии), `bot_action_selected`
  (улица и тип действия, без карт) и `persistence_error`.

### Сознательные отклонения

- Палитра: основная кнопка залита `#2F5FD6`, а не `#396EF2`, потому что белый текст на `#396EF2`
  даёт контраст 4.48:1, а это ниже AA. Вторичный текст на сукне — `#DDEBE4`, потому что `#C3CFDA`
  на сукне даёт 4.25:1.
- Сбросить карты, когда можно сделать чек, движок не разрешает: это защита от случайного тапа.
- Компоненты VKUI не используются. Стол нарисован по макету, а от VKUI взят системный шрифтовой стек.

## Дуэль с другом (2.0)

Два человека играют по ссылке-приглашению из VK. Тот же движок `poker-core`, что в Solo, работает
на сервере нативно. Сервер — единственный источник истины: клиенты получают только свой вид стола
и отправляют только намерения (`check`, `raise_to 120`). Solo по-прежнему работает в браузере
через WASM и от сервера не зависит. Если `VITE_PVP_URL` при сборке не задан, кнопки «Играть
с другом» на главной нет.

```text
VK Mini App (игрок A) ─┐                     ┌─ poker-core (общие правила)
                       ├─ WSS ─ pvp-server ──┤
VK Mini App (игрок B) ─┘                     └─ SQLite: комнаты, счёт встреч
```

### Как устроено

- **Вход.** Клиент отправляет `POST /api/auth` с `window.location.search`. Сервер проверяет
  подпись параметров запуска VK: HMAC-SHA256 по `vk_*` с защищённым ключом приложения,
  `vk_app_id` и возраст `vk_ts`. Только после этого `vk_user_id` считается личностью. Клиент
  получает сессию (12 ч) и одноразовый билет (60 с) для WebSocket. Секрет есть только на сервере.
  Имя и аватар клиент берёт из `VKWebAppGetUserInfo`: это только для отображения.
- **Комната** (`crates/pvp-server/src/room.rs`) живёт по схеме `waiting → ready → playing →
  finished`. Из `waiting`, `ready` и `finished` она может перейти в `closed`: по сроку, отмене
  или уходу игрока. В комнате ровно два места. Хозяин, открывший свою ссылку на другом
  устройстве, получает своё место обратно. Матч стартует один раз, когда оба нажали «Готов».
  Новое приглашение закрывает прежние пустые комнаты этого хозяина.
- **Ссылка.** Ссылка `https://vk.com/app<ID>#room=<id>` ведёт в конкретную комнату. Id — это
  128 случайных бит, он же секрет приглашения. В логах пишутся только первые 4 символа.
- **Протокол** (`protocol.rs`, версия 1). JSON по WebSocket. Каждый ход несёт `action_id` и
  `expected_state_version`. Повтор с тем же id применяется один раз, ход по устаревшей версии
  отклоняется. Сервер шлёт каждому игроку целый персональный снимок (`state_snapshot`)
  с возрастающим `server_seq`. После переподключения клиент просто рисует последний снимок.
- **Колоды** тасует сервер криптостойким генератором ОС (`getrandom`). Движок в дуэли не
  раздаёт из своего детерминированного генератора.
- **Таймеры** ведёт сервер: 20 с на ход плюс 30 с общего банка на матч. Когда время вышло,
  делается чек, если он возможен, иначе фолд. Если игрок отключился посреди матча, у него есть
  60 с на возвращение, потом ему засчитывается техническое поражение. Если отключились оба,
  матч отменяется без результата. «Сдаться и выйти» — техническое поражение сразу после
  подтверждения. Закрытие VK считается обрывом связи, а не сдачей.
- **Хранение.** Комната вместе с полным состоянием матча записывается в SQLite после каждого
  изменения, счёт встреч пары хранится отдельно. После перезапуска или деплоя сервер поднимает
  открытые комнаты, даёт обоим 3 минуты на возвращение и не запускает часы хода, пока не
  вернётся тот, чей ход. Поэтому пауза сервера не стоит никому матча.
- **Защита.** Разрешённые `Origin` задаются списком: CORS для `/api`, проверка при WebSocket.
  Кадр не больше 8 КБ. Не больше 60 сообщений за 10 с. Соединение без трафика 45 с
  закрывается. Одна живая вкладка на аккаунт: новая вытесняет старую. Не больше 3 комнат с
  гостем на хозяина. В логах нет токенов и подписей.
- **Наблюдаемость.** `GET /health` отдаёт комнаты по статусам, число соединений и счётчики:
  ошибки входа, переподключения, принятые и отклонённые ходы, технические поражения, ошибки
  записи и среднее ожидание друга.

### Запуск на VPS

Рабочий вариант — Docker по схеме [bots-server](https://github.com/OlegDurandin/bots-server):
GitHub Actions (`.github/workflows/docker.yml`) прогоняет тесты и публикует образ
`ghcr.io/olegdurandin/blitz-pvp:sha-…` (`latest` — только из `main`), а сервер его скачивает:
`./bots.sh 62.109.4.100 deploy blitz-pvp sha-…`. Адрес — `https://pvp.62-109-4-100.sslip.io`
(Caddy хоста → `127.0.0.1:8787`), база — `bots/blitz-pvp/data/pvp.db`, её копирует
ночной `bots-backup`. Клиент берёт адрес из `web/.env.production`.

Без Docker:

1. Соберите сервер: `cargo build -p pvp-server --release`, бинарник будет в `target/release/pvp-server`.
   Если ОС на VPS другая, соберите на нём самом. Нужен Rust, SQLite встроен.
2. Заполните `/etc/blitz-pvp.env` по образцу `crates/pvp-server/.env.example`: `VK_APP_ID`,
   `VK_APP_SECRET`, `PVP_DB`, `PVP_ALLOWED_ORIGINS`.
3. Установите `deploy/pvp-server.service` и поставьте перед сервером HTTPS-прокси.
   В `deploy/Caddyfile.example` Caddy сам получает сертификат и проксирует WebSocket.
4. Соберите клиент с адресом сервера и выложите его как обычно:
   `cd web && VITE_PVP_URL=https://pvp.example.ru npm run deploy`.
5. Проверка: `curl https://pvp.example.ru/health`.

Обновление сервера — замена бинарника и `systemctl restart pvp-server`. Матчи переживают
перезапуск (см. «Хранение»). Миграций нет: схема создаётся при первом запуске, версия
записана в `PRAGMA user_version`.

### Проверка вдвоём на двух аккаунтах VK

1. Аккаунт A: откройте Mini App → «Играть с другом» → «Пригласить» → отправьте ссылку
   аккаунту B в личные сообщения (или «Скопировать ссылку»).
2. Аккаунт B, на другом устройстве: нажмите ссылку. Должен открыться экран «… приглашает
   сыграть», а не главная. Нажмите «Присоединиться».
3. Оба нажимают «Готов» и играют. Проверьте, что у каждого видны только свои карты.
4. Посреди раздачи закройте приложение у B и откройте снова: у A сначала «… переподключается»,
   потом B возвращается к тому же столу.
5. После матча: «Предложить реванш» у одного и «Принять» у другого.
6. Повторите шаг 2 на iOS, Android и в веб-версии VK. Формат ссылки с `#room=` нужно проверить на
   каждой платформе. Если где-то ссылка ведёт на главную без комнаты, сообщите: сменим формат
   в `web/src/pvp/config.ts` (`inviteLink`).

Локально без VK: `PVP_DEV_AUTH=1 cargo run -p pvp-server` (работает только на 127.0.0.1),
затем `cd web && VITE_PVP_URL=http://127.0.0.1:8787 npm run dev`. Откройте два окна:
`http://localhost:5173/?dev_user=1` и `?dev_user=2`.

### Столы с друзьями (`table_room.rs`)

Кроме дуэлей сервер ведёт столы на 2–4 места: люди и боты вместе. Сообщения протокола
`create_table`, `join_table`, `table_add_bot`, `table_remove_bot`, `start_table`, `table_action`,
`table_again`, `leave_table`; ответы `table_created`, `table_preview`, `table_snapshot`.
- Хозяин сидит на месте 0 и выбирает 3 или 4 места. Друзья садятся по ссылке или коду: код у
  столов и дуэлей общий, `find_room` и `peek_room` отвечают `table_preview`, если это стол.
- Пустые места хозяин может отдать ботам (каждого не больше одного раза). При старте пустые
  места убираются, оставшийся порядок становится местами движка `Table`.
- Боты ходят на сервере (`bot::decide_table`) после паузы `bot_think_ms`. У людей таймер хода и
  банк времени, как в дуэли.
- Ушёл или не вернулся за минуту — сброс и выбывание до конца матча (у кого фишки уже кончились,
  тот уходит с заработанным местом). Ушли все люди — стол закрывается: боты сами не играют.
- После матча «Ещё раз» начинает новый, когда согласились все оставшиеся люди.
- Столы хранятся в SQLite (таблица `tables`) и переживают перезапуск сервера.

Клиент: `screens/TableOnline.tsx` (приглашение, лобби, игра, итоги), стол — тот же `Ring.tsx`.
Старые клиенты столов не знают, но дуэли у них работают как раньше.

### Платформы: VK, Telegram, браузер

Одна сборка клиента и один сервер дуэлей на все платформы, общее пространство
комнат: игрок из VK и игрок из Telegram садятся за один стол.

**Сервер** (`crates/pvp-server`):
- `player.rs`: `PlayerId` с платформой: VK (`1..2^61`, как раньше; в базе ничего не
  менялось), Telegram (`2^61 | user.id`), гость (`2^62 | хеш ключа браузера`). Одинаковые
  номера в VK и Telegram — разные игроки. Счёт встреч считается между любыми платформами.
- Вход (`server.rs`, `identify`): ровно одно доказательство на запрос:
  `launch_params` (VK, `vk.rs`), `tg_init_data` (Telegram, `telegram.rs`: HMAC от токена
  бота), `guest_key` (браузер, только при `PVP_GUEST_AUTH=1`). Имя и аватар из Telegram
  подписаны и важнее присланных клиентом.
- Платформа включается своим секретом: `VK_APP_SECRET`, `TG_BOT_TOKEN`. Нужен хотя бы один.
- Новая платформа: модуль проверки подписи, диапазон в `PlayerId`, ветка в `identify`.

**Клиент** (`web/src/platform/`):
- `types.ts`: интерфейс `Platform`: вход, имя, поделиться, ссылка-приглашение, комната
  из запуска. Остальной код к SDK мессенджеров не обращается.
- `vk.ts` (vk-bridge, ссылки `vk.com/app<id>#room=`), `telegram.ts` (`initData` из
  `#tgWebAppData`, SDK `telegram-web-app.js`, ссылки `t.me/<bot>/<app>?startapp=room_<id>`),
  `browser.ts` (гость по коду).
- `index.ts` выбирает платформу при запуске: Telegram → VK → браузер.
- Ссылка открывает игру в мессенджере хозяина. Другу из другого мессенджера — **код
  комнаты**: он работает везде.

**Подключить Telegram:**
1. В @BotFather: бот → `/newapp` (Mini App), короткое имя приложения, URL игры
   (тот же хостинг или любой HTTPS с этой сборкой).
2. Сервер: `TG_BOT_TOKEN` в `.env` (секрет), домен хостинга в `PVP_ALLOWED_ORIGINS`.
3. Клиент: `VITE_TG_BOT` (имя бота без @) и `VITE_TG_APP` (короткое имя Mini App) в
   `web/.env.production` — без них в Telegram нет ссылок-приглашений, только код.

## Третий не лишний: стол с ботами

Отдельный режим на главной: вы и 2–3 бота за одним столом. Движок `poker-core/table.rs` — тот же
холдем на 2–6 мест:
- позиции: при трёх и больше малый блайнд ставит следующий за баттоном, до флопа первым ходит
  игрок после большого блайнда; вдвоём — правила дуэли;
- побочные банки, неуравненная часть ставки возвращается; при делёже лишняя фишка уходит первому
  слева от баттона;
- неполный олл-ин-рейз не открывает торговлю тем, кто уже ходил;
- матч идёт целыми кругами (3 места — 9 раздач, 4 — 8), блайнды растут раз в круг: каждый
  ставит каждый уровень одинаковое число раз;
- без фишек игрок пропускает оставшиеся раздачи; места считаются по фишкам, вылетевший позже
  стоит выше. Если фишки кончились у вас, можно сразу перейти к итогам.

Вдвоём `Table` играет ровно как `Match`: тест `heads_up_matches_the_duel_engine` сверяет их после
каждого шага на 3000 случайных партиях.

Боты за столом (`bot/src/table.rs`): шансы считаются Монте-Карло против всех оставшихся, у
каждого свой диапазон по его агрессии; диапазон открытия сужается с каждым игроком, который ещё
будет ходить; блефов меньше с каждым лишним соперником. Когда за столом остались двое, бот играет
логикой дуэли без изменений. `cargo run -p bot --release --example table_arena 60`, по 60 столов
на каждую тройку характеров, средний результат за стол:

| Бот | Фишки за стол | Первое место |
|---|---|---|
| Алекс | +83 | 39% |
| Тихон | +67 | 35% |
| Пикси | +15 | 34% |
| Рекс | −15 | 34% |
| Сэм | −150 | 26% |

## Соперники

На главной можно выбрать одного из пяти ботов (`web/src/game/opponents.ts`). Все играют по одной
стратегии из `crates/bot`, но с разными настройками (`Style`): шире или уже диапазоны, чаще или
реже ставки, блефы и коллы, разные размеры ставок. Новичку добавлена случайная ошибка в оценке руки.

`cargo run -p bot --release --example evaluate personas 100`, по 200 матчей на пару, средний
результат в фишках за матч (шум около ±30):

| Бот | Стиль | vs random | vs station | vs tight-aggr | vs Алекс | Фолд префлоп | Ставки/коллы | Фолд на ставку |
|---|---|---|---|---|---|---|---|---|
| Пикси | новичок | +134 | +200 | +50 | −74 | 14% | 1.7 | 25% |
| Сэм | любит уравнивать | +195 | +205 | −16 | −71 | 12% | 1.1 | 17% |
| Тихон | осторожный | +140 | +224 | +36 | −16 | 37% | 2.6 | 37% |
| Алекс | сбалансированный | +203 | +203 | +66 | (сам с собой) | 23% | 2.8 | 34% |
| Рекс | агрессор | +208 | +129 | +76 | −4 | 13% | 3.7 | 32% |

Подписи сложности в интерфейсе (лёгкий / средний / сложный) взяты из колонки «vs Алекс».
Тест `opponents_have_distinct_styles` проверяет, что стили действительно различаются, а
`novice_is_easier_than_alex` — что новичок слабее Алекса. Настройки Алекса совпадают с 1.1,
поэтому его игра не изменилась (цифры стенда повторились один в один).

## Бот Алекс

Бот получает только `PlayerView` своего места и не видит колоду, карты человека и состояние ГСЧ.
Любое его решение проходит через фильтр легальности (`sanitize`). Стратегия приблизительная, это
не решённый чарт:

- **Префлоп.** Руки ранжируются по эквити heads-up против случайной руки (таблица из 169 классов).
  Диапазоны зависят от позиции и эффективного стека: на баттоне бот открывает около 66% рук при
  стеке больше 16 ББ и 58% при 10–16 ББ, иногда лимпит. На большом блайнде он защищается по шансам
  банка, делает 3-бет с топ-9% и изредка блефует 3-бетом. При стеке до 10 ББ играет пуш/фолд
  (56–85% рук в зависимости от стека).
- **Постфлоп.** Эквити считается методом Монте-Карло (600 прогонов) против диапазона соперника,
  суженного по его агрессии, и учитываются флеш-дро и двусторонние стрит-дро. Бот ставит на добор,
  полублефует, делает продолжающие ставки после префлоп-рейза, иногда разыгрывает ловушку или
  блефует. У каждого приёма своя ограниченная частота. Колл сравнивается с шансами банка, а для дро
  до ривера добавляется небольшая поправка на будущие выигрыши.
- **Размеры ставок** от трети до полного банка, кратны 5. В маленьких банках бот ставит не меньше
  60% банка, поэтому не делает постоянных минимальных ставок.

Решения детерминированы для конкретной точки матча, поэтому после перезагрузки бот повторит тот же
ход. В WASM одно решение занимает медиану 2.6 мс и максимум 5.7 мс (1085 решений, вместе с
JSON-обменом).

### Оценка (`examples/evaluate`)

Каждая сдача играется дважды, и во второй раз игроки меняются местами. Так везение с картами
почти взаимно гасится. 300 сдач × 2 места на каждую пару. Соперники: случайные легальные ходы,
«колл-станция», простой тайтово-агрессивный бот (`src/reference.rs`) и замороженная копия бота 1.0.
Шум при 600 матчах около ±15 фишек за матч.

| Бот | vs random | vs calling station | vs tight-aggressive | 1.1 vs 1.0 |
|---|---|---|---|---|
| 1.0 | 65% побед, +187 | 70%, +233 | 63%, +51 | — |
| 1.1 | 66% побед, +196 | 70%, +233 | 67%, +71 | 48%, +1 фишка |

| Поведение (все три соперника) | 1.0 | 1.1 |
|---|---|---|
| Олл-ин первым на префлопе, доля решений | 17% | 14% |
| Минимальный размер среди ставок на флопе | 19% | 0% |
| Минимальный размер среди ставок на тёрне / ривере | 8% / 8% | 0% / 0% |
| Фолд на префлопе | 18% | 21% |
| Олл-ин первым на ривере, доля решений | 9% | 13%, из них 79% со стеком не больше банка |
| Нелегальные действия | 0 | 0 |

По силе 1.1 не хуже 1.0: заметно лучше против тайтово-агрессивного соперника, в остальных парах
в пределах шума. Улучшения касаются поведения: исчезли минимальные ставки, стало меньше пушей до
флопа, появились позиционные диапазоны, учёт дро и продолжающие ставки. Цели «непобедимого» бота нет.

Тесты бота (`cargo test -p bot --release`):
- 20 000+ решений в разных состояниях, где сама стратегия, ещё до фильтра, всегда легальна;
- бот не коллирует ставки от половины банка со слабой рукой (эквити < 25%);
- нет патологий: пушей меньше 15% решений на каждой улице, минимальных ставок меньше 15%, доля
  фолдов на ставку от 10% до 70%;
- бот в плюсе против всех трёх эталонных соперников, решения воспроизводимы.
